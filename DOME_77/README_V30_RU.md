# DOME v30 — Control Center / Feature Flags / Pricing Config

Главное изменение v30: коммерческие и функциональные настройки вынесены из Python-кода.

## Как открыть управление на компьютере

Запустите:

`start_dome_control_center_windows.bat`

Откроется локальная страница `http://127.0.0.1:8766`.

Там можно без нового ZIP менять:

- включение/выключение функций DOME;
- режим «не продавать новым» для функции;
- наценку обычного урока: месяц / год;
- минимальную месячную и годовую цену;
- прибыль поверх себестоимости урока по интересам;
- процент страхового резерва;
- срок доступа к оплаченному уроку;
- число повторений;
- длительность trial;
- какие платные сервисы учитывать в Cost Engine;
- фиксированную долю расходов сервиса, если она не может быть получена автоматически;
- доступные изучаемые языки;
- параметры мягких уведомлений;
- номера редакций юридических соглашений.

## Файлы

Настройки сохраняются в `config/`:

- `features.json`
- `pricing.json`
- `languages.json`
- `notifications.json`
- `legal.json`

Ключи и токены по-прежнему НЕ хранятся здесь. Секреты остаются в `.env` / Railway Variables.

## Feature flags

Поддерживаются состояния:

- `enabled` — функция включена;
- `disabled` — функция выключена;
- `no_new_sales` — не предлагать/не продавать новым пользователям, но не ломать уже приобретённый доступ.

Резолвер уже поддерживает будущую иерархию:

GLOBAL -> LANGUAGE -> COURSE -> LESSON.

Рискованные функции оставлены выключенными по умолчанию: random child matching, group lessons, live paper handwriting, pose tracking, realtime reading.

## Pricing engine

Обычные курсы по умолчанию:

- месяц: себестоимость урока + $6 за каждый новый урок, минимум $49 за платёжный период;
- год: себестоимость урока + $5.80, минимум $490 за 12 месяцев;
- оплаченный урок доступен 10 месяцев;
- максимум 3 прохождения;
- trial 7 дней.

Уроки по интересам по умолчанию:

`рассчитанная себестоимость + резерв 15% + $30 прибыли за каждый новый урок`.

Все значения изменяемы из Control Center.

Важно: v30 создаёт управляющий слой и Pricing/Feature API. Не все будущие механики автоматически стали реализованными только потому, что у них есть переключатель. Переключатели нужны, чтобы функции можно было подключать поэтапно без переделки структуры проекта.
