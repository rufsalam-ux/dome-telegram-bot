# DOME v70 — RUNTIME AUDITED

Версия собрана из v69 после повторного аудита **реального пути ребёнка**, а не только структуры файлов. Это именно DOME / BilingvaDom с тремя курсами. К боту публикаций Telegram-канала и к Proof of Learning эта сборка отношения не имеет.

## Главный результат

Новый урок после этой версии должен добавляться через администрирование: основной PDF/PPTX → инструкция → ДЗ → видео/файлы/ссылки → AI-карта → ручная правка → validation → preview → publish. Для обычного нового урока новый ZIP не нужен.

## Что дополнительно исправлено после v69

1. **Персональная недельная выдача 1/2/3/4.**
   - Источник истины — `Subscription.lessons_per_week` конкретного ребёнка.
   - Перестановка или вставка урока в каталог не создаёт лишнюю недельную квоту.
   - Смена тарифа или повторная подписка начинает новый release-сегмент без «долга» за старые недели и без искусственной задержки.
   - Уже открытые уроки не исчезают после отмены; прекращается только будущая выдача.

2. **Единый entitlement для legacy-разговорного урока и content_v1.**
   - Нормальный лимит — 2 завершённых прохождения.
   - Незавершённая сессия не расходует новое прохождение.
   - Срок — 10 месяцев от `unlocked_at` каждого выданного урока.
   - Администратор может явно дать дополнительное прохождение через `/extrarun`.

3. **Мультфильм разговорного курса.**
   - Создаётся только после первого завершения.
   - Второе завершение не запускает новый мультфильм.
   - Импортированный разговорный урок теперь реально входит в ветку сборки мультфильма.
   - Если первая сборка технически упала, runtime-снимок с голосом/изображениями сохраняется; перед вторым прохождением бот пытается восстановить мультфильм ещё раз без списания прохождения.
   - Есть ручной recovery: `/retrycartoon child_id lesson_id`.

4. **Resume.**
   - Текущий шаг и runtime-состояние сохраняются.
   - После выхода ребёнок возвращается к незавершённому шагу.
   - Интерактивное ДЗ также хранит `current_step` и продолжается с места остановки.

5. **Импорт без риска потерять рабочий урок.**
   - Новый импорт сначала строится в staging-папке.
   - Рабочая версия заменяется только после успешной подготовки.
   - Перед re-import создаётся версия для rollback.
   - Ошибка импорта не удаляет опубликованный/рабочий урок.

6. **Видео и дополнительные материалы.**
   - На шаге extras принимаются документы, Telegram-video и ссылки.
   - Подпись `слайд 11` или имя `slide_11.mp4` привязывает материал к странице.
   - Непривязанные файлы и ссылки сохраняются на уровне урока и не теряются.
   - `video_pause_question` имеет отдельный Mini App: видео останавливается, вопрос должен быть решён корректно, только после этого урок идёт дальше.

7. **AI-разбор инструкции.**
   - Полная инструкция передаётся AI вместе с изображениями страниц.
   - Формат «5 слайд: ...» больше не обязателен: AI должен сопоставлять обычную прозу со смыслом страницы.
   - Номерная/табличная привязка остаётся дополнительным deterministic fallback.

8. **Строгая validation.**
   Публикация блокируется, если механика не исполнима: нет правильного ответа, targets, pairs, hotspots, координат, reading text/turns, video source, pause question и т.п. Проверяются и урок, и ДЗ.

9. **Preview/Test Mode.**
   - `/previewlesson lesson_id` запускает тот же runtime, что видит ребёнок.
   - Preview не списывает прохождение, не выдаёт ДЗ и не создаёт мультфильм.
   - Невалидный урок/ДЗ в preview не запускается.

10. **Versioning / rollback.**
    - Перед значимыми правками создаются snapshots.
    - `/lessonversions lesson_id`
    - `/lessonrestore lesson_id version_name`

11. **«Читайка» — исправлены конкретные механики первого урока.**
    - Слайды 6 и 14 — настоящий spatial drag-and-drop букв А/У, а не имитация кликами.
    - Слайды 7,8,9,16,17,18,19,24 — письмо/обводка.
    - Слайд 25 — tap-to-hear.
    - Слайд 26 — matching.
    - Видео на 3 и 11 сохраняются.
    - Строгая validation урока и ДЗ проходит.

12. **«Книжные истории» — чтение по ролям.**
    - Исправлены сцены, которые раньше были помечены `read_roles`, но не имели последовательности реплик.
    - Ребёнок выбирает персонажа; бот читает остальные роли по очереди.
    - Если ребёнку трудно, бот может взять отдельную сложную реплику и снизить долю текста ребёнка; при успешном чтении доля снова растёт.
    - Исходные страницы сцены показываются по ходу реплик, не дублируясь отдельными runtime-шагами.
    - Исправлен отсутствовавший video source в уроке.

13. **Универсальная Mini App-библиотека.**
    Есть отдельные runtime-механики для voice/repeat/reading/roles, choices, multi-select, matching/memory, drag-drop/sorting/sequence, builders, fill-gap, sound position, tracing/handwriting/drawing/coloring/maze, dictation, connect-lines, hotspots/interactive scene, video pause question и др. Для администратора добавлены понятные алиасы: `true_false`, `pronunciation`, `tap_to_hear`, `sequencing`, `letter_builder`, `mini_dictation`, `highlight_text`, `sound_to_letter_image`, `role_reading`, `reading_aloud`.

14. **Администрирование после урока.**
    - `/resendhomework child_id lesson_id` — повторно отправить существующее ДЗ в бот и email, не создавая дубликат assignment.
    - `/resendreport child_id lesson_id` — заново собрать и отправить родителю отчёт.
    - Автоматические authored-отчёты включают понятное описание количества голосовых/интерактивных заданий и повторных попыток.

15. **Webhook/payment lifecycle.**
    - Stripe webhook сначала резервирует уникальный `event_id`, затем применяет side effects.
    - Повторная доставка одного события не создаёт повторную подписку/выдачу.
    - Ошибка обработки откатывает reservation, чтобы Stripe мог корректно повторить событие.
    - Cancel/past-due не удаляет уже существующие `LessonEntitlement`.

16. **Persistence DOME проверен отдельно.**
    - DOME хранит SQLite, импортированные уроки и platform settings через свой `storage_root`.
    - Он не должен наследовать `/data` только потому, что `/data` используется другим Telegram-ботом.
    - Для Railway volume DOME путь задаётся **явно** через `STORAGE_ROOT` / `DATA_DIR` и `DATABASE_URL`. Перед изменением переменных конкретного работающего DOME-сервиса сначала проверить его текущий volume и данные.

## Рабочий workflow нового урока

`/addlesson reading lesson_002 Название` → основной файл → инструкция → ДЗ → extras → `/done_extras` → `/lessonmap` + `/hwmap` → `/validate_lesson` → `/previewlesson` → при необходимости `/slidetype`, `/slideconfig`, `/slideprompt`, `/hwtype`, `/hwconfig` → `/publishlesson`.

Обычная публикация/редактирование контента после этого не требует redeploy. Новый код/ZIP нужен только для принципиально новой runtime-механики или системного изменения.

## Проверки этой сборки

- Целевой regression/runtime-набор v63–v70: **44 passed**.
- Все bundled `content_v1` уроки + ДЗ проходят текущую строгую validation.
- Импорт проверен интеграционно: PDF → instruction → extra video mapping → re-import version → искусственная ошибка → рабочая версия сохранилась.
- SQLAlchemy-модель проверена на чистой SQLite-схеме: новые поля и composite uniqueness entitlement создаются.
- Все Python-файлы `app/` и `tools/` проходят syntax compile.
- JavaScript универсального Mini App проходит `node --check`.
- Широкий исторический набор без двух тестов, требующих отсутствующих в sandbox `aiogram`, даёт те же **22 устаревших legacy-fail**, что и исходный v69: они проверяют давно заменённые формы первого demo-урока/старые literal-строки, а не новые runtime-инварианты.

## Что нельзя честно назвать проверенным в этом окружении

В sandbox нет установленных `aiogram` и `aiosqlite`, поэтому здесь нельзя провести настоящий live Telegram polling + async SQLite end-to-end с Telegram/SMTP/Stripe/OpenAI. Эти зависимости есть в `requirements.txt` и устанавливаются Docker/Railway. После deploy нужен короткий smoke-test на реальном DOME-сервисе: `/version` → тестовый тариф → первый урок → выход/возврат → завершение → ДЗ → второе прохождение → lock, а также один admin preview/import.

Для «Книжных историй» текущая реализация слушает чтение **последовательными голосовыми фрагментами/репликами**. Это не непрерывный скрытый захват микрофона: Telegram/браузер требует явного разрешения на запись. Адаптивная помощь и распределение ролей работают на этих фрагментах.
