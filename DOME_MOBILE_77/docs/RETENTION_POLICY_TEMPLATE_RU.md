# Retention policy — шаблон для настройки

Не задавайте произвольные сроки только ради «защиты от споров». Для детских данных действует принцип минимизации.

Рекомендуемая архитектура (конкретные сроки утверждаются после юридической проверки):
- исходное аудио: минимально необходимый срок для ASR/QA/movie render, затем auto-delete либо более длительный срок только при отдельной обоснованной цели/согласии;
- transcript/progress: пока нужен для обучения/отчётов и установленного retention периода;
- movies: пока доступны семье или до запроса удаления / установленного срока;
- consent/purchase/evidence: отдельный юридически обоснованный retention, не смешивать с сырым детским аудио;
- deletion jobs: журнал факта удаления без сохранения удалённого контента.
